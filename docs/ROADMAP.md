- 更新日: 2026-10-17
- 状態: **データモデルと実例の初期ドラフトを記録済み。地図・比較カード・OpenPOI試作コード登録済み／実機QA・公開前**
- リポジトリ: https://github.com/yama-books/basho-atlas
- 開発方針: 地点の文学比較体験を最初に成立させ、地図と現代POIを後付けで検証する。

## 0. 初回完成像（MVP）

- PC/スマホのWebページで、深川～千住・武隈の松・松島の3地域を選べる。
- **武隈の松1地点だけは**人の典拠監査を終えた文学比較カードがある。
- 「古歌」「芭蕉の旅」「現在」を行き来できる。
- 作品中の順序と、史料に基づく実際の順序が違うときには区別して表示。
- 地図に正確な根拠のあるポイントのみを表示。曖昧な経路は推定として表示／あるいは初期は描かない。
- 現代POIを表示した場合は、出典・ライセンスを明示し、データの限界を示す。
- 公開GitHub Pagesでスマホ検証できる（公開操作は人の確認を得る）。

## 3. 開発技術（検討案）

- GitHub Pagesで配る静的Webアプリを優先。
- TypeScript + Vite + Leaflet を第一候補。まず小さなUIを試作し、必要性が確認できるまで重いフレームワークを追加しない。
- 作品データの正本は検証可能なJSON／Markdown。座標監査後にGeoJSONを生成する。
- OpenPOIはユーザーの操作に応じて問い合わせる。取得の遅延・失敗・帰属をUI設計の最初から扱う。
- CIは速いlint、型検査、JSON schema/参照テスト、静的ビルドを優先。ブラウザ実機・史料監査をCI合格で代替しない。
- 外部サービスの規約・API仕様が変わっても文学カードが壊れないよう、POIレイヤーを独立させる。

技術選定は**実装決定前の候補**。今回インストールやGitHub Pages設定はしない。
