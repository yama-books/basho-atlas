# 芭蕉歌枕マップ 基礎構想書

- **文書版**: v0.1（企画・調査統合版）
- **作成日**: 2026-10-16
- **状態**: 構想段階。仕様・典拠・利用許諾の確定前
- **想定プロダクト**: Webアプリ（PC・スマートフォン対応）
- **仮称**: 芭蕉歌枕マップ / 芭蕉の道、いまの道。
- **対象**: 『おくのほそ道』を軸とした、芭蕉の旅・歌枕・先行文学・現在の地理
- **扱い**: 後日GitHubへ登録するための基礎文書。**この文書の作成時点ではGitHubへのアップロード・公開・実装はしていない。**

> **中心の問い**  
> 芭蕉は何を見に行ったのか。目の前の景色か、歌や物語に蓄積された「文学の記憶」か。そしてその場所には、いま何があるのか。

## 1. 企画の目的

本アプリは、松尾芭蕉『おくのほそ道』に登場する歌枕・名所・旅の地点を、単なる観光地や地図上のピンとしてではなく、**時代を重ねて読むことのできる場所**として提示する。

一つの地点について、原則として次の三つの層を結び付ける。

1. **芭蕉以前の文学**: 先行和歌・物語・連想語・伝統的な歌枕のイメージ。
2. **芭蕉の旅**: 『おくのほそ道』本文、芭蕉・曾良の句、実際の旅・訪問記録とその確度。
3. **現代の場所**: 現在の道路・地形・施設・景観、近現代の土地利用変化。

目指すものは「芭蕉の通行経路をなぞる観光地図」だけでも「歌枕辞典」だけでもない。**歌枕が何を受け継がれ、どのように詠み直され、現在の場所とどう向き合えるかを学ぶ教材**である。

### 想定利用場面

- 中学・高校の古典授業（『おくのほそ道』、和歌、歌枕、文学史）
- 地理・歴史・国語をつなぐ探究学習
- 芭蕉の足跡を辿る旅行の予習・現地探訪
- 一般利用者の文学散歩と自主学習

### 非目的（初期段階）

- 全行程の史実に基づく徒歩ナビゲーションの完成
- 全歌枕について芭蕉の先行作品参照を断定すること
- OpenPOIの収録施設を「営業中」「現存確認済み」と保証すること
- AIのみで古典本文・影響関係・正解を確定すること

## 2. 競合調査から得た結論

2026-09-19に作成した『芭蕉歌枕マップ_競合調査メモ_2026-09-19.md』の調査と、そこに記録された後続のコード・データ監査を基礎とする。

| 先行例 | 既に実現していること | 新アプリで追加価値になり得ること |
| --- | --- | --- |
| [おくのほそ道：芭蕉の行きて帰りし物語マップ（hosomap）](https://kiritter.github.io/hosomap/) | 旅程、歌枕、本文、芭蕉・曾良句、旧地図・航空写真。補足に西行・能因・定家など先行文学も存在する | 先行文学を全地点で統一的に構造化し、時間軸・比較カード・学習の問いで扱う |
| [日本のデジタル文学地図（DLM）](https://literarymaps.nijl.ac.jp/) | 歌枕の位置、和歌・物語・謡曲・文学的連想を横断的に収録 | 『おくのほそ道』という一つの旅に絞り、先行文学・芭蕉・現代を教材順序で接続する |
| 桐原書店・教科書関連の地図教材 | 歌枕と『おくのほそ道』の旅程の地図上の組み合わせ | 比較学習のインタラクション、根拠の明示、現代情報の切替 |
| 自治体・観光地図、芭蕉ウォーク等 | 地域案内、旅程追体験、ウォーキング連動など | 古典作品の継承・変形を中心に据えた教材設計 |
| 紙媒体の『奥の細道』歌枕解説・旅行ガイド | 旅程順の歌枕と先行和歌の対応付け | 統一データによる地図検索・比較・授業利用・現代の地点情報との連動 |

**重要な修正履歴**: 初期仮説ではhosomapの古歌接続は限定的と考えたが、公開GeoJSONと表示処理を確認すると、遊行柳・武隈の松・笠島・色の浜などに先行文学への明示的な言及があった。したがって**「地図＋古歌＋芭蕉」は、それ自体では独自性にならない。**

### 本企画の差別化の柱

- **比較を本体にする**: 歌枕ごとに「古歌では／芭蕉は／現代では」を並べ、関係を読み解く。
- **先行作品の関係性を明示する**: 明示的な引用、研究上の有力な関連、一般的な歌枕の連想を混同しない。
- **地理の時間レイヤー**: 江戸時代の旅の記録と現代の場所を接続する。ただし過去の地図を確実な史実として偽装しない。
- **学習者の問い**: 選択・比較・探究を促す。単なる説明パネルで終わらせない。
- **出典と確度**: 学術的・教材的な情報の根拠、異説、未確認箇所を追跡できる。

## 3. 三つの時代レイヤー

### A. 芭蕉以前（文学的記憶）

各歌枕に、代表古歌・関連作品（初期は1〜3件）、作者、出典、該当地名、連想語、文学史的背景を紐付ける。

例: 武隈の松と能因、遊行柳と西行など。個々の本文や関連の強さは今後、信頼できる資料で確認する。

### B. 芭蕉の時代（1689年の旅と作品）

『おくのほそ道』の本文・芭蕉句・曾良句、旅の日付、場所への関わり方を示す。**『おくのほそ道』に書かれたこと、実際の移動の記録、後世の推定を別フィールドで管理する。**

### C. 現代（いま、その場所には何があるか）

現代地図、施設・店舗、駅・宿泊施設、現存する史跡、航空写真などを重ねる。必要に応じて、1970年代以降などの土地利用変化を別レイヤーとして加える。

**現代の施設情報は、過去の歌枕や史跡の継続性を証明するものではない。** 「近傍に存在するとデータに登録されている施設」と明示する。

## 4. 主要機能案

### 4.1 地図ビュー

- 芭蕉の旅程、確認済み訪問地点、本文に登場する歌枕、関連名所を表示。
- 歌枕・地名・章・地域・文学作品・人物で検索。
- 「文学」「芭蕉の旅」「現代施設」「旧地図・航空写真」をレイヤー切替。
- 地図から地点を選択して、その地点の比較カードを開く。
- スマートフォンでは地図と下部の情報シートを行き来できる軽量UIを優先。

### 4.2 地点の比較カード（企画の中核）

1. **地点名**（現在の地名、歴史的名称、異表記）
2. **歌枕としての姿**（古歌・物語・連想語）
3. **芭蕉の記録**（『おくのほそ道』本文と句、訪問・言及の区別）
4. **古典の比較**（何が受け継がれ、どう再解釈されたか。解釈と事実を分けて表示）
5. **現在の周辺**（地図・施設・交通・現在の写真への出典付き導線）
6. **学習の問い**（短い選択問題、根拠を探す記述・比較課題）
7. **典拠と検証状態**（資料、ライセンス、確度、異説）

### 4.3 「時代を切り替える」操作

- **芭蕉以前**: 古歌・物語・歌枕の蓄積を中心に表示。
- **1689年**: 芭蕉の旅・『おくのほそ道』を中心に表示。
- **現代**: 現代の地図・施設・土地利用を表示。
- **比較**: 複数の時代をサイドパネルまたは切替カードで並べる。

注意: 1689年モードは当時の完全再現地図ではない。使用した歴史地図の年代や再構成の根拠を表示する。

### 4.4 授業・探究モード

- 「なぜ芭蕉はこの歌枕を訪ねたと考えられるか」など、出典付きの問い。
- 先行歌と芭蕉の本文・句を左右（スマートフォンでは上下）に並べて読む。
- 現代との比較では「周辺施設が変化した事実」と「文学的価値の変化」を混同しない問いを採用。
- 将来的に授業用の地点セット、共有URL、プリント・PDF出力などを検討。

## 5. OpenPOI APIとの組み合わせ

- **公式ドキュメント**: https://docs.openpoiapi.com/
- **API**: https://api.openpoiapi.com/
- **出典・ライセンス案内**: https://openpoiapi.com/attribution.html
- **仕様確認日**: 2026-10-16

### 5.1 役割

OpenPOIを**現在のPOI（Point of Interest、施設・店舗）情報を取得するレイヤー**として使用する。過去の道・歌枕の位置をOpenPOIから決めたり、史実を推定したりはしない。

典型的な用途:

- 「武隈の松から500m以内の施設」
- 「芭蕉の旅程を表示している地図範囲内の現在の駅・施設」
- 「深川～千住周辺で、現代の街並みを構成する施設」
- 「文学名所の周辺にある宿泊・飲食等の検索」（現地探訪モード）

### 5.2 公式仕様で確認したこと

- `GET /v1/search` でキーワード、中心座標 `center=lng,lat` と半径 `radius`（m）、矩形 `bbox=minLng,minLat,maxLng,maxLat` による施設検索が可能。
- `GET /v1/suggest` は施設名などの入力候補用。現代の施設検索を自作する際の補助として検討。
- `limit` は検索で最大200件。地点周辺と地図表示範囲を分けて小さく取得する。
- APIキーなしで利用可能。ただし将来の規約・提供方法変更の可能性あり。
- レスポンスには施設名、住所、緯度経度、分類、データソース、`licenses`、`attributions` 等が含まれる。
- 配信データは複数ソース由来。**一括して同一ライセンスとみなさない**。
- レート制限は現時点ではAPI全体で定常200 req/s、バースト600 req/s。高頻度の全行程スキャンはしない。
- 店舗の閉業残存、位置誤差、未収録、カテゴリの不完全さ、鮮度を個別に判定できない点に注意。

### 5.3 呼び出し例（概念例。座標は必ず確定データから渡す）

```http
GET https://api.openpoiapi.com/v1/search?center={経度},{緯度}&radius=500&limit=100
```

地図全体を対象とする場合は `bbox` を使える。`bbox` があれば `center+radius` より優先される。

### 5.4 推奨する取得設計

1. 地点の初回表示時は、**その地点周辺だけ**POIを検索。
2. 「現代施設」レイヤーを明示的にONにしたとき、表示範囲検索を実行。
3. 地図の移動・拡大縮小にはデバウンスやキャッシュを利用し、無制限に再取得しない。
4. 結果数上限とカテゴリ別フィルタを設ける。多い場合は「取得した最大件数の範囲内」と明示。
5. 施設重複、座標の誤差、半径と経路からの距離を検証。
6. `licenses` と `attributions` を結果と共に保持し、表示・再配布時の条件を満たす。
7. 「POIに収録されている」ことと「いま営業している」ことを明確に区別。

### 5.5 位置と経路の扱い

- **確実な地点**: 本文や信頼できる史料により関連・訪問が確認できる地点。ただし座標は史跡の位置・比定地の違いに注意。
- **推定地点／推定経路**: 史料や研究から再構成した位置・道筋。確度と典拠を表示。
- **現代の代替経路**: 現代の道路網で移動できるルート。**芭蕉がそこを歩いたという意味ではない。**
- 「通った道の今」を見るときは、まず確認済み地点を結び、推定区間の線は別の線種・凡例で区別。

## 6. 外部データの候補と権利境界

| ソース | 目的 | 利用上の扱い |
| --- | --- | --- |
| [日本のデジタル文学地図：データセット](https://literarymaps.nijl.ac.jp/dataset/) | 歌枕・関連和歌・物語・謡曲・地理情報 | 公式ページに **CC BY 4.0**。出典・ライセンス・変更点を明示。実データの収録範囲と本文の扱いを確認 |
| [OpenPOI API](https://docs.openpoiapi.com/) | 現代の店舗・施設・位置情報 | APIと各施設の出典・ライセンス条件を確認、帰属表示を実装 |
| [国土地理院](https://maps.gsi.go.jp/) | 現代地形図、航空写真、旧版地図等 | サービス・タイル・資料単位の利用条件と表示義務を確認 |
| [国土数値情報](https://nlftp.mlit.go.jp/ksj/) | 近現代の土地利用・鉄道等 | 個別データの利用条件、年代・分解能・精度を確認 |
| 『おくのほそ道』・『曾良旅日記』等の信頼できる本文・研究資料 | 芭蕉の旅程と本文、場所の比定、文学的解釈 | 底本・異同・版本・出典を管理。現代語訳・解説文の著作権を別途考慮 |
| hosomapの公開リポジトリ | 競合の機能と表現の参考 | **調査対象に限定**。明示的な再利用許諾が確認できるまでGeoJSON・解説を取り込まない |

### DLMデータの確認済みの範囲

公式データセットページ（2026-10-16閲覧時の表示）は、文学名所101件、資料336件、和歌1,951首等のXLSXデータを公開し、ライセンスをCC BY 4.0と記載している。**公式ページ記載の最終更新日は2026-03-23**。旧競合調査メモには2026-09-17更新との記載があるため、日付の由来は後で照合する。現時点で9月17日を「公式データセット更新日」として確定しない。

### 公開前の必須事項

- 各外部データの帰属・ライセンス・改変表示を整理した `DATA_SOURCES.md` の作成。
- 著作物本文・現代語訳・写真を無許諾でまとめて再配布しない。
- 未確認の影響関係や場所比定を公開の確定情報にしない。
- 競合の公開ソースを自作のデータとしてコピーしない。

## 8. 初期データモデル案

地点・古典作品・文学的関連・現代施設を混ぜずに保存し、関係テーブルで接続する。

```yaml
place:
  id: place_takakuma_matsu
  name: 武隈の松
  name_variants: []
  category: candidate_utamakura
  geometry:
    type: Point
    coordinates: null # 精査前の座標は捏造しない
    location_status: pending
  visit_status: pending # visited / mentioned / inferred / disputed 等
  confidence: pending
  sources: []
  review_status: pending

literary_relation:
  place_id: place_takakuma_matsu
  work_id: null
  author_id: null
  relation_type: pending # explicit_quote / likely_reference / shared_topos 等
  interpretation: null
  sources: []
  review_status: pending

basho_record:
  place_id: place_takakuma_matsu
  source_work: 奥の細道
  passage_id: null
  haiku_ids: []
  travel_date: null
  date_basis: null
  sources: []
  review_status: pending

modern_poi:
  source: openpoi
  place_id: place_takakuma_matsu
  fetched_at: null
  results: [] # 各結果にlicensesとattributionsを保持
```

上記はフィールド構造の**提案例**であり、学術的内容・具体的な座標・先行作品との関係を確定したデータではない。

### 必要なデータ管理原則

- `source`、`retrieved_at` / `fetched_at`、`license`、`review_status` を記録。
- **作品上の登場／実際の訪問／後世の比定**を別概念で持つ。
- **文学的解釈／確認できる事実**を別概念で持つ。
- **史料の成立年代／出来事の年代／現代データの取得日時**を混同しない。
- 人手未監査のAI案は `pending`。公開解説や正答としての利用には人の監査を要求。
- 外部APIのPOIは静的な正本ではなく**取得時点のスナップショット**として扱う。

## 9. 技術構成の暫定案

**初期は静的Webアプリ＋外部API**として小さく作る。

- UI: HTML/CSS/JavaScript。必要に応じてTypeScriptなどを選定。
- 地図: Leafletなどの軽量ライブラリ。地図タイルと帰属表示は提供元条件に従う。
- 独自データ: 監査可能なMarkdown/JSON/YAMLとGeoJSON。本文・位置・関連を分割して管理。
- 現代施設: OpenPOI APIを表示に応じて呼び出す。
- 配信: GitHub Pagesを第一候補とする（リポジトリ・公開範囲は未確定）。
- キャッシュ: まずクライアント側の短期キャッシュ。保存・再配布条件を確認した上で拡張。
- サーバー: MVPでは原則不要。API利用制限や機能要件次第で再検討。

### UI方針

- 歌本文・本文引用は読みやすい明朝系を中心にし、操作UIは現代的で簡潔なゴシック系。
- 地図とカードを主役にし、和風装飾を過剰に重ねない。
- 「昔／芭蕉／今」の切替は画面全体の移動を抑え、スマートフォンでも直感的に使える。
- 推定・未確定の情報は色だけに依存せず、ラベル・線種・説明で区別する。
- 地図・本文・ライセンス情報のいずれも画面サイズによって隠れないことを重視。

| **P0：正本・権利境界の確定** | 本構想、競合メモ、データソース台帳、公開方針 | 取り込んでよい資料と未確認資料が分離される |
| **P1：文学比較カード** | 典拠つきの3地点カード、暫定スキーマ、学習の問い | 古歌→芭蕉→現代の三層が一地点で理解できる |
| **P2：地図＋OpenPOIの試作** | 地図、地点ピン、周辺POI取得、帰属表示 | 深川～千住／武隈／松島で動作を確認 |
| **P3：学習機能** | 比較表示、検索、問い、授業用の地点セット | 読むだけではなく学習者が判断・比較できる |
| **P4：歴史地図・時代比較** | 旧地図・航空写真・土地利用年代切替（権利確認後） | 現代地図と史料の差を誠実に表現できる |
| **P5：現地探訪・公開拡充** | GPS、共有URL、他の歌枕への拡張 | 実機・ライセンス・典拠監査を通過 |

### 最小のMVP

- 3地域の地図表示
- 少なくとも1地点の**典拠監査済み**「古歌→芭蕉→現代」比較カード
- OpenPOIによる地点周辺の現在施設表示（出典付き）
- 「訪問確実／推定／本文に言及のみ」を区別
- スマートフォン対応
- 出典、帰属、免責、検証状態の表示

初回から全旅程・全歌枕を網羅することは目標にしない。

## 11. 調査・検証が必要な論点

### 学術・教材

- 『おくのほそ道』の底本・表記方針、本文異同、曾良の記録との対応。
- 歌枕の選定基準（古典上の歌枕／名所／芭蕉が言及した地名の区別）。
- 先行和歌の選定理由と関連の強さ（直接典拠を断定しない）。
- 各地点の座標の根拠、比定地が複数ある場合の表現。
- 生徒向けの問いと教師向けの典拠・解釈メモの分離。

### 技術

- OpenPOIが実際の試作地点でどの程度の施設を返すか。
- 現代地図のPOI密度、キャッシュ、API障害時の表示、重複除去。
- 道筋の再構成資料の確保。実証段階では「点中心」で始める妥当性。
- 地図タイル・航空写真のスマートフォン性能と利用条件。
- 地理座標、検索範囲、距離計算の単位と精度。

### 運用・公開

- 公開リポジトリの名称・所有者・配置、GitHub Pagesの利用方針。
- DLM・OpenPOI・地図提供者のライセンス記載、更新時の追従方法。
- 競合との比較を続け、機能の重複・独自性を実機で評価する。
