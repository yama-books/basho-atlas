## 1. レビュアーの責務と境界
- GitHub上の実コード・Diff・Actionsログ・作業者の実機操作記録を参照して**採否を判定する**。作業者の自己申告のみで実機成功や歴史資料の正確性を確定しない。
- 二つの子PRを混ぜず、CoreとUIを**別ゲート**として査読してから親branchへ統合する。元の親PR #1を直接mainへマージ/公開することは別の明示決裁とする。
- 完全性過剰検証をしない。ユーザーが実際に触る「検索→年代→判定の理由→地図参照→出典」が動くかと、誤情報・操作不能・権利違反を最優先。
- 古地図の紙媒体調査・未デジタル史料調査はPAUSED。子PRに図版や復元境界を無理に追加することを要求しない。

## 2. 監査開始時の読み込み
1. 子PRの`base.ref`、`head.ref`、開始コミット、changed files、review statusを取得。**main向けに誤提出されていたらマージせずbase修正を求める。**
2. 親PR #1（開発中/未マージ）の最新HEADと変更パス、過去CIを確認。子PR側の変更を未取り込みの親PRと比較して、差分を正確に特定。
3. 作業者結果文書（`docs/OLDMAP_CODEX_RESULT_20261020.md` / `docs/OLDMAP_CLAUDE_RESULT_20261020.md`）から使ったNode/ブラウザ環境、テストコマンド、未検証事項を読む。
4. 親branchとの競合、意図しない既存ファイル変更、権利属性の勝手な`human_approved`化、不要なアセット・トークン追加を監査。

## 3. Core子PR（必須合否）
| 判定軸 | 受入条件 | 停止例 |
|---|---|---|
| API互換 | `createProvinceAtlasService`、検索、年パース、年別判定が旧呼出例のまま正常 | 関数名やstatusを無断変更しUIが破綻 |
| 年代厳密性 | 1689 P010/P002をID対応だけ、1868陸奥を境界年保留、1185讃岐の境界未収録 | 1868にP115へ自動確定、1185に幕末の図形を適用 |

| 資料・安全 | 出典、位置精度、候補ステータス、権利未承認を保持 | `redistribution_allowed=true`の根拠なき付与 |
| 実装量 | UIから切り離した純関数+適切なテスト、重複検索ロジックの排除 | 過剰なフレームワーク/別エンジン作成 |
| 検証 | PR最新HEADで`npm run check`合格、追加テストは実際の失敗ケースを検出 | ソース文字列存在だけの大量テスト |

## 4. UI子PR（必須合否）
| 判定軸 | 受入条件 | 停止例 |
|---|---|---|
| 導線 | 武蔵1689→陸奥P002/P115→1868保留→讃岐1185未監査→参照点と出典が操作可 | 検索が隠れる、結果選択で失われる、未監査を確定表示 |

## 5. 合流順・親PRの品質ゲート
1. Coreの子PRをレビュー：互換・境界・テスト・資料権利をチェック。修正指示が必要ならPRを維持して具体的な差分を返す。
2. Core採用決定後、**明示の統合判断**に従って親branchへ取り込む。親PR #1（main対象）は未マージのまま。
3. UI子PRを最新親branchへ更新してテスト/E2E・競合解消。Core新APIを取り込む接着コードが必要ならUI側の所有範囲で小差分にし、余分な中間レイヤーを作らない。
4. UIが受入基準を満たした後、親ブランチ上で`npm run check`とブラウザ主要シナリオを再評価。仮にCIが成功しても、データ源を読み違えたら合格にはしない。
5. 親PRをDraft→Ready、mainマージ、GitHub Pages公開するタイミングは**ユーザーが別途承認**する。作業者や監査担当は無断で実行しない。

## 6. 必須・非ブロッキングの仕分け
**必須P0**：アプリの起動不能/表示不能、検索→年判定の矛盾、現代点を歴史事件地点と誤断定、無許諾画像、国境の捏造、主要操作不能、セキュリティ・個人情報漏えい。
**P1（v0.3の使い勝手）**：狭幅で操作しにくい、タイル取得失敗を黙殺、選択が分かりにくい、キーボード操作できない。
**非ブロッキング**：全88件の読みの出典付き網羅、全国全時代の境界、非デジタル古地図、代表地点の数、精度が学術的に不明な地物の復元。これらは明示的に未収録と表示。
監査のために無数のソースの重複調査をさせない。証拠不足の項目は`unknown`または`not_audited`で保留し、UI機能は前進させる。
